# Writing the guide from a session

## Reader and voice

Write for a stranger to the topic. That includes the user months later, who may have forgotten most of it. Apply explanatory-writing for structure, pacing, terminology, and evidence: introduce ideas in the order the reader needs them, define terms before using them, and keep sources beside claims.

The session log changes two of explanatory-writing's defaults:

- **Views recorded in the log are the user's own.** State them as the user's views or in first person, as the topic's existing documents do. Do not neutralize them into generic advice. Views that are not in the log still must not be attributed to the user.
- **The log sets the scope.** The guide covers what the session covered. Turn the questions the user asked into the guide's questions and the topic README's index entries.

## Material the log does not cover

A stranger may need context the session skipped, such as a definition the user already knew or a step needed to connect two ideas. Add only what the reader needs to follow the guide. Keep additions short, and list each one in the audit list.

Do not expand into subtopics the user did not discuss. List them as possible gaps in the audit list instead. Leave out topics the user explicitly set aside, or name them briefly as out of scope when a reader would expect them.

Carry unchecked claims into the guide only with a qualification, or check them now and cite the source. Turn open questions into a short "Open questions" section when they help a reader know where the guide stops.

## Audit list

Give the user the audit list in the chat reply, or in the pull request description if a PR is requested. Keep it out of the guide itself. It contains:

- **Additions:** each passage not grounded in the log, with its location in the guide and why a stranger needs it.
- **Reordering:** where the guide's order departs from the conversation, and why.
- **Checks:** claims checked during the write-up, with sources, and any claims still unchecked.
- **Possible gaps:** subtopics a reader might expect that the session did not cover.

If an item cannot be grounded in the log or a source, raise it with the user rather than writing it in.
